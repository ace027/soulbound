<objective>
Stand up Vitest and write the test the retrospective specifically asked for: proof that the World Voice contract guard **fails** when it should. Tests were pulled forward from Phase 4 because three of Phase 1's eleven review defects were introduced by fixes, with no regression net to catch them.
</objective>

<context>
Read `.planning/phases/02-backend-world-voice/02-CONTEXT.md`, then `shared/src/worldVoice.ts` — particularly `assertWorldVoiceContract`, `extractPromptContractFieldPaths`, and `CONTRACT_FIELD_NAMES`.

**Why this specific test.** Phase 1 shipped a guard that runs at backend startup and throws when the prompt, the derived JSON Schema, and `CONTRACT_FIELD_NAMES` disagree. It was verified once, by hand, by renaming a field and watching the process exit 1 — then the rename was reverted and the check was never encoded anywhere. It is the load-bearing enforcement of `CLAUDE.md` constraint #4 and it currently has no regression protection of its own.

A test that only asserts the guard passes on the current prompt is nearly worthless: it would still pass if `assertWorldVoiceContract` were gutted to `return`. **The test that matters asserts it throws.**

Note that `package.json`'s root `test` script was deliberately removed in Phase 1 because no workspace defined one. Restoring it is part of this plan.
</context>

<task id="2">
<action>
Write `backend/src/__tests__/contract.test.ts` with these cases:

1. **Passes on the real prompt** — `assertWorldVoiceContract(WORLD_SYSTEM_PROMPT)` does not throw.
2. **Throws on a prompt-only rename** — take the real prompt, rename `gm_note` to `gm_notes` **in the string only**, and assert it throws. Assert the thrown message names both the missing and the unexpected field. This is the case `tsc` cannot catch, because the type and the schema move together while the prompt does not.
3. **Throws on a missing field** — remove a contract field from the prompt's RESPONSE FORMAT block; assert it throws naming that field.
4. **Throws when the RESPONSE FORMAT block is unparseable** — corrupt the JSON; assert a clear error rather than a silent pass.
5. **The derived schema matches `CONTRACT_FIELD_NAMES`** — all nine paths, compared as sorted arrays.

**Operate on in-memory copies of the prompt string.** Do not write to `backend/src/data/worldSystemPrompt.ts` — it is a byte-identical verbatim extraction and a test that mutates it on disk risks leaving it corrupted if the run is interrupted.
</action>
<verify>
`npm test` passes with all five cases. Then temporarily stub `assertWorldVoiceContract` to a no-op, re-run, and confirm cases 2-4 **fail** — proving they test the guard rather than merely exercising it. Restore and re-run. Paste both results.
</verify>
<done>Five cases cover pass, prompt-only drift, missing field, unparseable block, and schema agreement — and the negative cases were demonstrated failing against a gutted guard.</done>
