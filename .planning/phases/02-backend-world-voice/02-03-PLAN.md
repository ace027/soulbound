<context>
Read `.planning/phases/02-backend-world-voice/02-CONTEXT.md`, then `backend/src/anthropic.ts` (plan 02-01, complete), then the artifact's three functions in `legacy/souldbound-world.jsx`:

| Function | Lines | System blocks | Route |
|---|---|---|---|
| `determineUniqueSkill` | 383-432 | **none at all** | `POST /api/unique-skill` |
| `callWorldEngine` | 446-499 | `buildSystemBlocks()` | `POST /api/world-engine` |
| `generateIntroScene` | 502-522 | `buildSystemBlocks()` | `POST /api/intro-scene` |

**These three are in one plan deliberately.** `PROJECT.md` records that this codebase's recurring failure mode is drift *between* the call sites — `generateIntroScene` once concatenated the system prompt into the user message and silently lost caching for months. Splitting them across three agents is the mechanism that produces that drift. Build them together and check them against each other.

**Read the legacy prompt-construction code before writing any of them.** The user-message content for each is assembled from character data, game state, and questionnaire answers in specific ways. Port that assembly faithfully — the wording is part of what makes the World Voice work, and `determineUniqueSkill`'s prompt in particular is the adversarially stress-tested surface documented in `docs/design-decisions-log.md`.

Model IDs come from `MODELS` in `config.ts`. Do not write a model string in a route file.
</context>

<action>
Write `backend/src/routes/worldEngine.ts` (`POST /api/world-engine`) and `backend/src/routes/introScene.ts` (`POST /api/intro-scene`).

**They must produce byte-identical system blocks.** That is what puts them in one cache namespace: same model, same system prefix. Intro scene runs once per playthrough and warms the cache for the World Engine loop; if their system blocks differ by a byte, that benefit vanishes silently.

World engine's user content (legacy lines 450-484) carries current skills with mastery, location and scene, the last 5 actions, the original soul profile, and the last 8 Unique Skill usage notes. Intro scene's (legacy 503-507) asks for an opening scene and instructs `world_events: [{type:"scene_set", location, scene_summary}]`. Port both faithfully.
