## Prompt fidelity — rendered strings, byte-identical

The agent extracted each legacy template **mechanically** (reading between the backticks, CRLF→LF only, never retyped) and diffed rendered output against identical sample inputs:

- unique-skill vs legacy 385–418: **byte-identical**, 1540 chars
- world-engine vs legacy 450–484: **byte-identical** on two cases — full state, and an empty-state case exercising the opposite branch of both ternaries
- intro-scene vs legacy 502–507: **byte-identical**, 569 chars

Spot-checked independently: the legacy prompt contains **single-space "blank" lines** (` ` not empty), and the route file preserves them exactly, em-dashes included. That is precisely the whitespace trap that would survive a careless port.

**No wording drift in any of the three.**

The agent's own first verification attempt failed because it hand-typed the legacy reference functions and lost those single-space lines. It correctly identified the failure as being in its *test scaffolding*, not the port — the route files were generated by splicing extracted text and were never at risk — and regenerated the reference mechanically. Worth noting that it diagnosed which side was wrong rather than adjusting the port to match a bad oracle.

## Decisions flagged, accepted
- **Lazy `await import('../config.js')` inside each handler** rather than a static top-level import. `server.ts` imports the route files statically, so a static config import in a route would reproduce the no-key import throw. Consistent with `anthropic.ts`'s pattern.
- **Two `?.` / `?? {}` additions** in `renderWorldEnginePrompt` where legacy plain JS relied on a ternary having already proven a value defined — TS strict mode can't narrow through that across a nested template literal. Verified to change nothing about the rendered string, on both branches.
- **Passed Zod schemas, not the derived JSON-Schema constants.** My plan text said "Schema: `UNIQUE_SKILL_JSON_SCHEMA`" — that was shorthand and wrong: `zodOutputFormat` takes a Zod schema, and those constants are reserved for the drift guard. The agent followed the committed `anthropic.ts` contract over my plan's wording, which was the right call.

## Orchestrator fix
The agent flagged that `anthropic.ts`'s doc comment said the SDK normalizer "strips `$schema` entirely" when it actually folds `$schema` and `enum` *values* into prose `description` annotations — the keys are gone, the information survives. The outcome claim was right, the mechanism description wasn't. Corrected, with a note to check for the key rather than the substring, since that exact confusion produced a false failure during plan 02-01's verification too.
