<objective>
Build `backend/src/anthropic.ts`: the single module through which every World Voice call passes. No routes yet — this is the helper the routes in plan 02-03 consume.
</objective>

<context>
Read `.planning/phases/02-backend-world-voice/02-CONTEXT.md` first, then `backend/src/config.ts` and `shared/src/worldVoice.ts`.

**Why this module exists.** `PROJECT.md` records this codebase's recurring failure mode: drift between the three call sites, not any one being wrong. A previously-fixed bug had `generateIntroScene` concatenating the system prompt into the user message, silently losing prompt caching for months. One shared helper is the structural answer — if the three routes each build their own request, that bug class returns.

Phase 1 already provides: `getAnthropicApiKey()`, `redact()`, and `MODELS` in `config.ts`; `WORLD_VOICE_JSON_SCHEMA`, `UNIQUE_SKILL_JSON_SCHEMA` in `@soulbound/shared`; `WORLD_SYSTEM_PROMPT` and `WORLD_LORE` in `backend/src/data/`. Consume them. Do not redefine model IDs here — `MODELS` is the one place they live (R6, already satisfied).

**Do not edit** `backend/src/data/worldSystemPrompt.ts` or `worldLore.ts`. They are byte-identical verbatim extractions carrying a balance-load-bearing MUST NOT list.
</context>

<task id="2">
<action>
Write the shared call helper — one function all three routes use. It takes: the model, the user-message content, an optional system-blocks flag, and the JSON schema for `output_config.format`. It returns the parsed, schema-validated response.

Requirements on every call it makes:
- `max_tokens: 16000` (CLAUDE.md #5 sets a floor of 2000; this is not a target to sit on)
- `output_config: { format: { type: 'json_schema', schema } }` using the schema passed in
- **No assistant prefill** — returns 400 on both models
- **No `budget_tokens`** — returns 400 on both models
- Model string passed through verbatim from `MODELS`, never with a date suffix appended

**Critical asymmetry**: the helper must support calls with *no `system` parameter at all*. `determineUniqueSkill` sends none — not merely no `WORLD_LORE`, but no system blocks whatsoever (CLAUDE.md #8). Passing an empty array is **not** the same thing and would change the adversarially-tested behaviour. Omit the key entirely for that path.

Validate the response against the Zod schema from `@soulbound/shared` before returning, so a malformed response fails here rather than in the frontend.
</action>
<verify>
Type-check passes. In a scratch script, call the helper with a stubbed client and assert the request object: `max_tokens === 16000`, `output_config.format.type === 'json_schema'`, no `budget_tokens` key, no assistant-role message, and — for the no-system path — that `'system' in request === false`. Paste the assertion output.
</verify>
<done>One helper builds every request, with max_tokens 16000, structured outputs, no prefill, no budget_tokens, and a genuine no-system path that omits the key rather than emptying it.</done>
</task>
