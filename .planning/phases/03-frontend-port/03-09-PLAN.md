<context>
Read `.planning/phases/03-frontend-port/03-CONTEXT.md` first — especially "Behavior tuned by feel".

Port target: legacy 786-1044 (state, effects, handlers), with the five screens now imported from
`screens/` and the turn logic from `game/applyWorldUpdate`.

**The selected architecture deliberately does NOT restructure the state graph.** Keep all 17
`useState` (787-804) and both `useEffect` (806-812) as legacy has them. Do not introduce a
`useGameSession` hook, a reducer, or a state machine. The Clean proposal offered exactly that and was
rejected: this state graph is the most behaviour-load-bearing and least-tested part of the port, and
rewriting it while claiming to "just move" it is how behaviour tuned by feel disappears silently.

Specific things that look like cleanups and are not:

- **`autoSave` runs inside a `setLog` updater** (1022-1027), reading `newState` and `currentSlotId`
  from closure. It looks like a misplaced side effect. Port it as-is. If you believe it is wrong,
  report it — do not fix it in this plan.
- **The two `newSkillIds` clear timeouts differ**: 2000 ms after the questionnaire (905), 2500 ms
  after an action (1012). Do not unify them.
- **`setNewSkillIds` receives only newly-granted names**, not evolved ones (1011).
- `handleQuestionnaireComplete` (865-911) contains the `Math.random()` intrinsic roll (877). It stays
  here — plan 03-04 deliberately kept it out of the pure module.
- `handleAction` shrinks to: guard → `api.callWorldEngine` → `applyWorldUpdate` → `set*` → autoSave →
  catch. The catch renders `"The World Voice fell silent. " + e.message` (1029).

This is the plan where a stale-closure or dropped-autosave regression would land, and no
pure-function test can see it. Task 3 is not optional.
</context>
