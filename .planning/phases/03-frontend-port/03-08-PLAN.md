<context>
Read `.planning/phases/03-frontend-port/03-CONTEXT.md` first.

Port targets: loading 1335-1344, simulation 1346-1440 (mobile branch then desktop branch).

**This is the CLAUDE.md #3 plan.** Two violations were confirmed by reading legacy:

1. **Line 1388**: `<div style={{ flex: 1, overflow: "hidden", display: "flex", flexDirection: "column" }}>`
   — missing `minHeight: 0` — whose child is a **Fragment `<>`** wrapping `WorldLog` + `ActionBar`.
   CLAUDE.md #3 states outright: never rely on a Fragment to act as a flex/scroll container; wrap it
   in a real `<div>`. Fix both: add `minHeight: 0` to the wrapper, and replace the Fragment with a
   real `<div>` carrying `display: flex; flex-direction: column; min-height: 0`.
2. `WorldLog`'s own root — fixed in plan 03-06. Verify it arrived; do not fix it twice.

The rule is *every* flex ancestor in the chain, not just the nearest. Walk the chain from the scroll
region up to the page root in **both** layouts and report what you find. This trap caused a real bug
in this project before.

**`isMobile` comes from `useIsMobile()`** (plan 03-05), not `window.innerWidth` at render time. That
is R12's first bug (legacy line 1348).

**This plan owns three of the six `<style>` blocks: 1338 (loading), 1354 (mobile sim), 1410
(desktop sim)** — legacy 1355 carries an `@import` inside the mobile block. Delete them; `index.css`
owns the keyframes and `index.html` the font `<link>`. Note from
Phase 1: the scrollbar thumb width differs between legacy copies (3px mobile, 4px desktop) and
`index.css` resolved it to 4px by plurality. That is a known, accepted difference — do not
"restore" the 3px.
</context>
