<objective>
Three typed fetchers against the backend routes, replacing the artifact's direct Anthropic calls.
This is where R12's missing `response.ok` bug gets fixed.
</objective>

<context>
Read `.planning/phases/03-frontend-port/03-CONTEXT.md` first.

Legacy lines 382-433 (`determineUniqueSkill`), 445-500 (`callWorldEngine`), 501-523
(`generateIntroScene`) called `api.anthropic.com` directly and **none of them checked
`response.ok`** — a non-2xx fell through to `JSON.parse` on an error body. That is R12's third bug.

**Almost none of those functions ports.** Prompt assembly, `buildSystemBlocks`, the
` ```json ` fence-stripping, and the model IDs all live backend-side now. What remains is a thin
POST + status check + schema parse.

Backend request shapes (from `backend/src/routes/`, which are the contract):
- `POST /api/unique-skill` — `{ name, race: { name }, answers: { nature, drive, flaw, memory, bond } }`
- `POST /api/world-engine` — `{ action, gameState }`
- `POST /api/intro-scene` — `{ character: { name, race: { name }, uniqueSkill: { skill_name, soul_resonance } } }`

Backend error bodies are `{ error: { message, code } }` with codes including `INVALID_REQUEST`,
`AUTHENTICATION_FAILED`, `RATE_LIMITED`, `UPSTREAM_UNAVAILABLE`, `UPSTREAM_ERROR`,
`INVALID_RESPONSE_SHAPE`, `PAYLOAD_TOO_LARGE`. Surface something the UI can show a player — legacy
renders `"The World Voice fell silent. " + e.message` (line 1029).

Validate responses with `WorldVoiceResponseSchema` / `UniqueSkillDeterminationSchema` from
`@soulbound/shared`. The backend already validates, but the client re-parsing is what makes
contract drift a test failure here rather than a runtime surprise.
</context>
