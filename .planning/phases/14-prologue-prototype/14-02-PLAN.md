- `export function isTrivialAction(text: string): boolean` -- `text.trim().length <= 2 || TRIVIAL_ACTION.test(text)`.
- `export function renderTranscript(history: PrologueHistoryEntry[]): string` -- each entry becomes `PLAYER ACTION — ${wrapUntrusted('player_action', text)}` (player) or `NARRATOR — ${stripDelimiters(text)}` (narrator), joined with `'\n\n'` (em dash U+2014, exactly as in the experiment).
- `export function renderBeatPrompt(history: PrologueHistoryEntry[]): string` -- `beat = number of player entries`; `idle = beat >= 2 && isTrivialAction(player[beat-1].text) && isTrivialAction(player[beat-2].text)`; returns `` `${NARRATOR_RULES}\n\nSCENE SO FAR:\n${renderTranscript(history)}\n${note}\n${BEATS[beat - 1]}\nWrite only the narration for this beat.` `` where `note` is `'\nSCENE NOTE: the player has not acted for two beats. The world moves on without them in this beat.\n'` when idle else `''` (identical to `playScene` in the experiment).
- `export function renderProfilePrompt(history: PrologueHistoryEntry[], canon: PrologueCanon): string` -- the experiment's `profilePrompt(transcript, canon)` verbatim with `renderTranscript(history)` in place of `transcriptText(transcript)`; `canon === 'scene'` selects the "You may refer to specific events of the scene." rule, otherwise the "Do NOT mention scene details ..." rule.
- A default-exported Express `Router` with `POST /api/prologue/beat` and `POST /api/prologue/profile`, async handlers wrapped like `uniqueSkill.ts` (`void handle(...)`), errors passed to `next`.
- Beat response body: `{ narration, beat, final }` validated with `PrologueBeatResponseSchema.parse` before `res.status(200).json(...)`, `beat = number of player entries`, `final = beat === 4`, `narration` trimmed. Profile response body: the `PrologueProfileSchema`-validated object returned by `callWorldVoice`.
- Request validation: `PrologueBeatRequestSchema.safeParse(req.body)` / `PrologueProfileRequestSchema.safeParse(req.body)`; failure -> a local `RequestValidationError` (status 400, code `INVALID_REQUEST`, message "Invalid prologue-beat request body: <issues>" / "Invalid prologue-profile request body: <issues>", issues rendered like `describeIssues` in uniqueSkill.ts).
- Model call (both routes): `callWorldVoice({ route: 'prologueBeat' | 'prologueProfile', model: MODELS.prologueBeat | MODELS.prologueProfile, content, useSystem: false, schema: PrologueNarrationSchema | PrologueProfileSchema })` with `MODELS` obtained by the same lazy `await import('../config.js')` as `uniqueSkill.ts`, for the same reason (copy its comment's reasoning in one sentence).
- `server.ts`: add `import prologueRouter from './routes/prologue.js';` between the `introSceneRouter` and `uniqueSkillRouter` imports (alphabetical), and `app.use(prologueRouter);` immediately after `app.use(introSceneRouter);` with a one-line comment "// Prologue routes (Phase 14, opt-in from the frontend): system-free, so they join no cache namespace."
Edge/error cases:
- Invalid body (wrong opening, bad alternation, 5 players, empty text, unknown key, missing history) -> 400 `INVALID_REQUEST`, no Anthropic call.
- Model output failing `PrologueNarrationSchema` (over 3000 characters, missing field) or `PrologueProfileSchema` -> `WorldVoiceCallError` `INVALID_RESPONSE_SHAPE` 502 via the existing handler (no new mapping).
- Refusal or any upstream error -> the existing `callWorldVoice` mapping (no new mapping).
- Player text containing `</player_action>`, `<PLAYER_ACTION >`, or nested `<play<player_action>er_action>` never reaches the prompt as a live tag; a narrator history entry containing any of those tags is stripped the same way.
- Two trivial actions in a row at beats 1 and 2 -> idle note present at beat 2; one trivial action, or trivial then non-trivial, -> no note; beat 1 never has the note.
- Missing or wrong Bearer passphrase (self-host harness) -> 401 `PASSPHRASE_REQUIRED` for the new routes, proving the gate covers them.
