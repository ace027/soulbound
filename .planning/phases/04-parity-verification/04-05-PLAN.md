<objective>
R14. The one thing no amount of mocking can establish: that the migrated app actually plays, against
a real backend and a real model, end to end.
</objective>

<context>
Read `.planning/phases/04-parity-verification/04-CONTEXT.md` first.

**This plan spends real money.** Measured 2026-09-17: **$0.0499 per cached world-engine turn**,
~$2.65 for a 50-turn session. Output tokens dominate at ~77%. A pause longer than 5 minutes costs
**+$0.087** on the next call because the cache expires. Character creation is three calls
(unique-skill on Sonnet, intro-scene on Opus, then the first world-engine turn).

**Budget before you begin: creation + 3 world-engine turns ≈ $0.25.** State your intended call
count up front and stop at it. Do not "just one more turn" to see what happens — this is the
developer's Console credit.

**Two blockers are already diagnosed. Do not rediscover them:**

1. **The key.** Use `SOULBOUND_ANTHROPIC_KEY` as the host env var — never `ANTHROPIC_API_KEY`,
   which Claude Code itself prefers over a Pro/Max subscription and would move the developer's own
   usage onto billed credits. `docker-compose.yml` maps it through; `backend/src/config.ts`
   fail-fasts without it.
2. **The CA.** A containerized World Voice call fails with `self-signed certificate in certificate
   chain` — the proxy CA is injected at build time for npm only and never reaches the runtime
   image's trust store. Not a product defect; the developer's machine does not TLS-intercept.
   Mount it, no Dockerfile change:
   `-e NODE_EXTRA_CA_CERTS=/ca/ca-bundle.crt -v /root/.ccr/ca-bundle.crt:/ca/ca-bundle.crt:ro`

Docker in this sandbox needs starting by hand — PID 1 is `process_api` with no service manager:
```
setsid nohup dockerd > /tmp/dockerd.log 2>&1 < /dev/null &
export NPM_CA_FILE=/root/.ccr/ca-bundle.crt
```
If it dies with "timeout waiting for containerd": `pkill -9 -x dockerd containerd && rm -f
/var/run/docker.sock /run/containerd/containerd.sock`, then retry. **Never `docker system prune`
without a re-pull path** — Phase 2 lost its final containerized verification to a Docker Hub 429
after pruning the cached base image.

**If no key is available**, run everything that does not need one, and report R14 **UNTESTED** with
exactly what remains. Phase 3's review established the standard: a criterion you could not test is
reported as untested, never as passing.

**The 15,132-token cache figure is stale** — two lines were later added to `WORLD_SYSTEM_PROMPT`,
which sits inside the cached prefix. Re-derive the expected number with `count_tokens` (free)
before spending anything on the live call, so you know what you are looking for.
</context>
