<context>
Read `.planning/phases/04-parity-verification/04-CONTEXT.md` first.

**Why this exists.** jsdom performs no layout. `getBoundingClientRect` returns zeros. The 129
frontend tests assert *declared* style properties — which does catch a removed `flex: 1` or
`minHeight: 0`, contrary to what Phase 3's plans originally claimed — but cannot see a panel that
has actually collapsed. Phase 3 fixed four `min-height: 0` violations; nothing automated would
notice a fifth appearing.

**Adding Playwright to `package.json` is deliberate here.** Phase 3 kept it out on purpose and
installed it to a scratch directory, because nothing in the repo needed it. That trade flips the
moment the guard is meant to be repeatable. Add it as a devDependency.

**Environment specifics, verified working:**
- The bundled Chromium is a different build than Playwright expects, so `executablePath` is
  **required**: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`.
- Do **not** run `npx playwright install` — it will try to download browsers and fail.
- `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` stops the npm postinstall re-fetching.
- Two console messages are expected sandbox artifacts, not defects: the Google Fonts stylesheet
  fails `ERR_CERT_AUTHORITY_INVALID` behind this environment's TLS-intercepting proxy, and
  `/favicon.ico` 404s because `index.html` declares none.

**Zero cost is mandatory.** Seed a `sbc-save:<id>` slot plus `sbc-save-index` into `localStorage`
via `addInitScript` *before* the app boots — the mount effect reads the index — then click Load.
`handleLoadSave` goes title → simulation with no API call. Do not exercise the creation flow here;
it needs three model calls or a stub swap, and neither belongs in a committed smoke test.
</context>

<task id="2">
<action>
Write `frontend/e2e/smoke.spec.ts`. Seed a save, load it, and assert what jsdom cannot, at both
375x800 and 1280x800:

- the world log's scroll container has `scrollHeight > clientHeight` — it genuinely overflows
- scrolling it changes `scrollTop` — it genuinely scrolls
- the action bar's bounding box is inside the viewport — it is pinned, not pushed off
- neither panel has collapsed: every flex ancestor of the scroll region has non-zero width AND height

The last one is the regression guard. Assert on real geometry via `boundingBox()`, never on a
declared style — a declared-style assertion here would duplicate the jsdom suite and prove nothing
new.

Then a resize case: load at 1280, resize to 375 without reload, assert the layout switched from the
two-panel desktop form to the tabbed mobile form. That is R12's first bug, and Phase 3 could only
demonstrate it by hand.
</action>
