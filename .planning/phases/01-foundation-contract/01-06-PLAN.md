<objective>
Wire the two services together with Docker Compose and prove the Phase 1 success criteria hold end to end — including that the backend fails fast and legibly when no key is present.
</objective>

<context>
This is the plan that closes Phase 1. Everything before it built pieces; this one demonstrates they run together.

`docs/MIGRATION-PLAN.md` specifies the key passes through as `environment: - ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}` on the **backend service only**. The frontend never receives it.

Docker secrets (file-mounted rather than env var) were considered and deliberately not adopted as the default: under plain `docker compose` without Swarm, a secret reduces to the same bind-mounted-file-on-disk reality as `.env`, just referenced differently. Documented as an optional hardening path for a deployer targeting a less-trusted host — not something to implement here.

Read `.planning/phases/01-foundation-contract/01-CONTEXT.md` first.
</context>

<tasks>

<task id="1">
<action>
Write `docker-compose.yml` defining both services:
- `backend`: builds from `backend/Dockerfile`, exposes 3001, receives `ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}` and nothing else secret
- `frontend`: builds from `frontend/Dockerfile`, exposes 5173, depends on `backend`, and reaches it by service name (not `localhost`, which resolves to the wrong container)

Add a healthcheck on the backend hitting `/api/health`, and make the frontend's `depends_on` wait on that healthcheck rather than mere container start — otherwise the frontend can come up against a backend that is still booting.

Ensure compose reads `.env` from the repo root for variable substitution.
</action>
<verify>
`docker compose config` renders without error and shows `ANTHROPIC_API_KEY` on the backend service and **absent** from the frontend service. Confirm the rendered output does not contain a real key value when `.env` holds one — check with a dummy value, not your own key.
</verify>
<done>Compose defines both services with a healthcheck gate, and the key is scoped to the backend alone.</done>
</task>

<task id="2">
<action>
Bring the stack up with a dummy `ANTHROPIC_API_KEY` value and verify the running system:

- `curl localhost:3001/api/health` returns `{"status":"ok"}`
- The frontend serves on 5173
- A request through the frontend's proxy path reaches the backend health route, proving inter-service networking works by service name

Then verify the negative case: stop the stack, unset the key, bring it up again, and confirm the backend exits with the actionable message from Plan 03 rather than crash-looping opaquely. Restore the dummy key afterward.
</action>
<verify>

</verify>
<done>The stack runs, services reach each other by name, and the missing-key failure mode is legible from compose logs.</done>
</task>
