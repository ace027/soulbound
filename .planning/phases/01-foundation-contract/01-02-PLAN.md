<objective>
Build the single module that makes `CLAUDE.md` constraint #4 mechanical: the World Voice JSON contract expressed once, as TypeScript types, with the JSON Schema for `output_config.format` derived from those same types. After this plan, prompt/parser drift is a compile error rather than a runtime surprise.
</objective>

<context>
This is the highest-leverage module in the migration. Phase 2's routes and Phase 3's frontend handlers both import from it.

The recurring failure mode in this codebase's history is drift between the three API call sites, not any single one being wrong — a previously-fixed bug had `generateIntroScene` concatenating the system prompt into the user message so it never cached. One shared contract source is the structural answer to that pattern.

**Read `legacy/souldbound-world.jsx` before writing types.** The contract is specified in two places that must agree:
- `CLAUDE.md` constraint #4 lists the required field names
- `WORLD_SYSTEM_PROMPT` (legacy lines 63–216) contains the actual JSON schema the model is instructed to return — the end of that string defines the response shape

If those two disagree on any field, **stop and report the discrepancy** rather than picking one. That disagreement would itself be the drift this module exists to prevent.

Also read the consumers to get the types right:
- `gameState` construction — legacy lines 890–897
- Initial `skills` array shape — legacy lines 875–881
- `character` / `uniqueSkill` shape — legacy lines 883–886
- `narrativeMemory` shape and its backward-compat default — legacy lines 896, 845–848
- Save-slot payload — legacy lines 815–827; save index metadata — legacy lines 28–36
- `TIER_STYLE` tier keys — legacy lines 525–531
</context>

<action>
Produce the JSON Schema for `output_config.format` **derived from** the types in task 1, not written by hand alongside them. Two acceptable mechanisms — pick one and justify it in a code comment:

Whichever you choose, the invariant is: **there is exactly one place a field name is written.** Adding a field to the contract without updating both the type and the schema must be impossible.

Export the schema as a named export. Add a comment stating that Phase 2 routes pass it to `output_config.format`, and that `additionalProperties: false` plus a correct `required` list are needed for strict validation.
</action>
