<critique_revisions>
**Binding. Plan critique 2026-09-24 (QA REWORK, security BLOCK). Where this section conflicts with the text above, this section wins.**

1. **Frame allow-list (security #5).**
   - Keep a stack frame only if its `filename` is under the app's `dist/`, under
     `node_modules/<pkg>/`, or starts with `node:`. Otherwise drop the frame, since multi-line error
     text can forge fake `at …` frames.
   - A kept frame's `function` must match `^[\w$.<>]{1,100}$`, or it becomes `'?'`. Then run
     `redact()` over function and filename.
   - The exception type must match `^[A-Za-z]\w{0,63}$`, or it becomes `'Error'`.
   - `code` is mapped through the known set of codes (the shared constants plus the Anthropic
     error codes in `anthropic.ts`), or it becomes `INTERNAL_ERROR`.
   - A thrown non-Error becomes `new Error('NON_ERROR')`.
   - The canary also asserts on the envelope header, including any `trace` block.
2. **Secret minimum lengths (QA #13, security #12).** `BETTER_AUTH_SECRET` must be at least 32
   characters. Every other hosted secret (`RESEND_API_KEY`, the OAuth client secrets, and the
   `DATABASE_URL` password when it has one) must be at least 16, or boot fails naming the
   variable. That stops a short value such as `postgres` from making `redact()` rewrite ordinary
   text. A password-less URL (the local test DB) is fine: there's nothing to redact. This amends
   R25d's "≥ 32" (spec Revision History row 21).
3. **`USER_RATE_LIMIT_PER_MINUTE`** (security #12, QA #16): a non-secret integer from 1 to 600,
   default 60, validated like `RATE_LIMIT_PER_MINUTE` (`config.ts:361-377`), used in hosted mode
   only. Export it; 06-04 uses it.
4. **Type-checking tests (QA, Verify commands).** `backend/tsconfig.json:24` excludes
   `src/__tests__/**`, so `npm run build` never type-checks test files. Run
   `npx tsc --noEmit -p backend/tsconfig.json` plus Vitest, and say in the SUMMARY that test-file
   type errors surface only when the tests run.
</critique_revisions>
