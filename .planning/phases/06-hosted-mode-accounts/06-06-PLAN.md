<critique_revisions>
**Binding. Plan critique 2026-09-24 (QA REWORK, security BLOCK). Where this section conflicts with the text above, this section wins.**

1. **The invite comes in the fragment** (`/#invite=CODE`; see 06-03 revision 8). In `main.tsx`,
   **before the first render or fetch**, read `invite` from `location.hash` and Better Auth's
   `error` from `location.search`, hold both in memory, and remove them with
   `history.replaceState`. This happens even for a signed-in player who never sees `SignIn`
   (security #10). `SignIn` receives the values as props.
2. Only **known** error codes map to messages. The raw `error` parameter is never rendered.
3. **A session that expires mid-game (QA #18):** in `api.ts`'s shared error path (`:218`, beside the
   `PASSPHRASE_REQUIRED` branch), add a `SIGN_IN_REQUIRED` branch that calls a new
   `emitSignInRequired()`. `ModeGate` subscribes to it and switches to `SignIn`. This adds a branch
   without changing existing behaviour, and the existing tests must pass unedited.
</critique_revisions>
