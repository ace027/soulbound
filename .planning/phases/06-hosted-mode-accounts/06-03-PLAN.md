<task id="2">
<action>
**`backend/src/invites.ts`**:
- `generateInviteCode()`: `randomBytes(16).toString('base64url')`.
- `hashCode(code)`: SHA-256 as a Buffer.
- `createInvite(pool, { expiresInDays? })`: inserts the hash and returns the code once.
- `redeemInvite(pool, code)`:
  - rejects anything not matching `INVITE_CODE_PATTERN`;
  - looks the invite up by hash, where it's unused, unexpired and not reserved by another nonce;
  - returns `{ inviteId }`, or `null` in every failure case (one path, so the responses are
    identical).
- Cookie helpers:
  - `inviteCookieKey(secret)` = `hkdfSync('sha256', secret, '', 'soulbound/sb_invite', 32)`;
  - `signInviteCookie({ inviteId, nonce, exp })` produces `base64url(payload).base64url(hmac)`;
  - `verifyInviteCookie(value)` uses `timingSafeEqual` and checks `exp`, returning the payload or
    `null`;
  - `COOKIE_NAME = '__Host-sb_invite'`, with attributes `Secure; HttpOnly; SameSite=Lax; Path=/; Max-Age=900`.
- `reserveInvite(pool, { inviteId, nonce })` and `consumeInvite(pool, { inviteId, nonce, userId })`
  implement the spec's SQL verbatim.
- `reconcileInvites(pool)` marks invites whose nonce matches a user created during the reservation
  window. Export it now; 06-05's purge calls it.

**`backend/src/auth.ts`**: `createAuth(deps: { pool, publicUrl, secret, emailFrom, sendEmail, google?, discord?, now? })`
returns `{ auth, handler, inviteContext }`.
- Options:
  - set explicitly, as must_haves list;
  - magic link with `storeToken: 'hashed'`;
  - Google and Discord only when their client ID and secret are both set.
- `inviteContext` is an `AsyncLocalStorage<{ invite?: InvitePayload; ip?: string }>`, plus a
  `withInviteContext(req, res, next)` wrapper that parses the `__Host-sb_invite` cookie from the raw
  `Cookie` header (no cookie-parser dependency), verifies it, and runs the handler inside the store.
- `databaseHooks.user.create.before`:
  - missing email → throw an `APIError` saying "An email address is required to create an account";
  - `emailVerified === false` → throw (before any reservation);
  - no valid invite → throw `INVITE_REQUIRED` with the cross-device message from the spec;
  - otherwise `reserveInvite`; no row → throw `INVITE_INVALID`.
- `after`: `consumeInvite`. If 0 rows, delete the user with a raw `pg` query, then throw.
- `session.create.after`: calls an injected `onSessionCreated(userId)`, a no-op now (06-05 wires the
  deletion-cancel into it).
- `sendMagicLink`:
  - if neither an account with that email exists nor a valid invite is in ALS → return silently;
  - if an in-memory per-email counter (3 per 15 min, using the injected `now`) is exceeded → return
    silently;
  - otherwise call `sendEmail({ from: emailFrom, to, subject, text })`.
  - Comment: the counter is in-memory because hosted runs as one instance (spec, Purge scheduling
    row); Phase 13 revisits it.

**`backend/src/scripts/createInvite.ts`** plus the `invite:create` script:
- reads only `DATABASE_URL` (like `migrate.ts`, no config import);
- prints `${publicUrl}/?invite=${code}` once if `BETTER_AUTH_URL` is set, otherwise just the code;
- stores only the hash.

Extend `selfhostNoPg.test.ts` only if `auth.ts` is reachable from `server.ts` (it shouldn't be until
06-04). Otherwise leave it.
