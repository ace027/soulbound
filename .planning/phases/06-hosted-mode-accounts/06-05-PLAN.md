<objective>
Let a player leave: deletion takes effect for access immediately, stays reversible for seven days,
and then removes the account for good, safely even with two instances running.
</objective>

<context>
Read `06-CONTEXT.md`, `06-04-SUMMARY.md` (`HostedDeps`, and how `DELETE /api/account` is mounted
when `requestAccountDeletion` is present), `06-03-SUMMARY.md` (the session-revocation API name
found in source; the `onSessionCreated` hook), then the spec: R24d, the Key Decisions rows "Deletion
grace" and "Purge scheduling", "Data and Control Flow" → Deletion, and the Failure Modes rows for
purge, old session and `after` failure.

Better Auth's own `deleteUser` is an immediate hard delete with no grace period (spec, Deletion grace
row), so **don't use it**. Revoke sessions with the API that 06-03 recorded (e.g.
`auth.api.revokeSessions`, or a direct `DELETE FROM session WHERE "userId" = $1`). Prefer the API if
it takes a user id server-side; say which you chose and why.

`pg_try_advisory_xact_lock` is released at commit, so a pooled connection can't keep holding it after
the job. Take it on a client checked out for this job alone (`pool.connect()`), inside `BEGIN`.
</context>
