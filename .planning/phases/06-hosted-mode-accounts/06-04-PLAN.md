<action>
`backend/src/hostedGate.ts` exports:
- `frameHeaders()`: sets `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'`.
- `originCheck(publicOrigin)`:
  - for methods other than GET/HEAD/OPTIONS under `/api`, it rejects a missing Origin, the literal
    `null`, any origin that isn't exactly `publicOrigin`, and `Sec-Fetch-Site: cross-site`;
  - on rejection it answers 403 with the `{ error: { message, code: ORIGIN_REJECTED } }` envelope;
  - no exemptions; the webhook slot is mounted **before** it.
- `sessionGate(auth, pool)`:
  - calls `auth.api.getSession({ headers: fromNodeHeaders(req.headers), query: { disableCookieCache: true } })`
    (confirm the option name against 06-03's table);
  - no session → 401 `SIGN_IN_REQUIRED`;
  - a session whose user has an `account_deletions` row → 401 `SIGN_IN_REQUIRED`;
  - otherwise sets `res.locals.user = { id, email }`.
- `userLimiter(perMinute, now)`: keyed by `res.locals.user.id`, 429 `TOO_MANY_REQUESTS`.
- `ipv6Slash64(ip)`: normalises `::ffff:` IPv4-mapped addresses to IPv4, and truncates IPv6 to its
  first 4 hextets. Unit-test it with ~6 cases in `hostedOrder.test.ts`, or a small self-host test

<critique_revisions>
**Binding. Plan critique 2026-09-24 (QA REWORK, security BLOCK). Where this section conflicts with the text above, this section wins.**

1. **The webhook slot matches exactly (security #2).** Express 5 routes are case-insensitive and
   non-strict, so the slot's handler calls `next()` unless `req.originalUrl`, with the query
   stripped, is exactly `/api/billing/webhook` and the method is POST.
2. **The Origin check is mounted with `app.use('/api', originCheck)`,** never a `startsWith` check
   (`server.ts:192-195`). Tests expect 403 for:
   - `POST /API/auth/sign-in/magic-link`;
   - `POST /api//auth/sign-in/magic-link`;
   - `POST /api/auth/../invites/redeem`;
   - a POST with `X-HTTP-Method-Override: GET`.
3. **`ipv6Slash64` expands the address first** (`::`, any `%zone`, `::ffff:`) and only then keeps
   the first 4 hextets. Tests show that `2001:db8::1`, `2001:db8:0:0::2` and the fully written form
   share one key. The redeem limiter uses the same `keyFor`.
4. **`frameHeaders()` also sets `Referrer-Policy: no-referrer`.** The selfhost-absence test covers
   it too.
5. **`hostedGate.ts` never imports `better-auth`.** `fromNodeHeaders` and `getSession` arrive through
   `HostedDeps` (QA #3), because `server.ts` imports `hostedGate.ts` statically.
6. **`HostedDeps` gains `reportError?`** (moved from the 06-01 stub) and `fromNodeHeaders`. The
   user limiter reads `USER_RATE_LIMIT_PER_MINUTE` from config (06-01).
7. `accessGate.ts`'s `createRateLimiter` gains an optional `keyFor`, defaulting to today's key. The
   existing limiter tests must pass unedited.
</critique_revisions>
